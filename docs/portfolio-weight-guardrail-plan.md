# 포트폴리오 비중 산정 및 가드레일 개선 계획

이 문서는 다음 작업자가 이어서 구현할 수 있도록 남기는 계획서입니다. 아직 구현 지침이 아니라, 현재 논의한 방향과 작업 범위를 정리한 참고 문서입니다.

## 배경

현재 시스템은 Gemini가 최종 리포트에서 종목별 `목표비중`을 생성하고, 코드는 그 값을 파싱해 HTML/PNG/Telegram/성과 추적에 사용합니다. 최근 개선으로 근거 없는 신규 종목은 코드에서 제거하고 해당 비중을 현금/대기자금으로 이동하지만, 비중 자체가 왜 그 숫자인지는 아직 충분히 설명되거나 검증되지 않습니다.

## 핵심 판단

비중 산정을 전부 코드 알고리즘으로 대체하지 않는다. 이 프로젝트는 메르 블로그의 맥락, 뉘앙스, A/S, 기존 포트폴리오 흐름을 해석해야 하므로, 비중의 1차 판단은 LLM이 맡는 편이 현실적입니다.

대신 코드는 투자 리스크와 형식 오류를 막는 가드레일 역할을 한다.

| 역할 | 담당 |
|------|------|
| 메르 글의 맥락 해석 | LLM |
| 종목별 투자 근거 판단 | LLM |
| 기존 보유 종목 유지/축소 판단 | LLM |
| 목표비중 1차 제안 | LLM |
| 근거 없는 신규 종목 제거 | 코드 |
| 단일 종목/시장/현금 비중 제한 | 코드 |
| 합계 100% 보정 | 코드 |
| 보정 내역 기록 | 코드 |

## 목표 구조

1. Gemini가 추천 종목과 목표비중을 제안한다.
2. Gemini는 각 비중의 산정 이유를 표에 명시한다.
3. 코드는 추천 표를 파싱한다.
4. 코드는 근거, 비중 합계, 단일 종목 상한, 현금 최소 비중 등을 검증한다.
5. 위반 항목은 보수적으로 보정하고, 보정 내역을 리포트에 기록한다.

## 프롬프트 개선 계획

`system_prompt.py`의 포트폴리오 추천 표에 `비중산정근거` 컬럼을 추가한다.

예상 표 형식:

| 종목명 | 코드/티커 | 판단 | 목표비중 | 근거유형 | 비중산정근거 | 핵심 근거 |
|--------|----------|------|----------|----------|--------------|-----------|
| [종목] | [코드] | 매수/Buy | X% | 직접언급/기존보유 | [비중을 그렇게 둔 이유] | [핵심 근거] |

프롬프트에 넣을 비중 원칙:

| 상황 | 비중 원칙 |
|------|-----------|
| 메르가 직접 비중을 제시 | 해당 비중을 최우선 보존 |
| 직접매수언급 | 상대적으로 높은 비중 가능, 단 상한 준수 |
| 단순 직접언급 | 소액/관망성 비중 우선 |
| 기존보유 | 기존 비중을 기준으로 유지/축소/확대 판단 |
| 섹터만 긍정 | 신규 종목 생성 금지, 기존 보유 조정 또는 현금 유지 |
| 불확실성 높음 | 현금/대기자금 확대 |

## 코드 가드레일 계획

`portfolio_validation.py`에 비중 검증 후처리를 추가한다.

| 검증 항목 | 처리 |
|-----------|------|
| 근거 없는 신규 KR/US 종목 | 기존 로직처럼 제거 후 현금 이동 |
| 단일 종목 상한 초과 | 초과분을 현금/대기자금으로 이동 |
| 전체 비중 합계 100% 초과 | 초과분을 위험도 낮은 순서로 감액하거나 현금 보정 |
| 전체 비중 합계 100% 미만 | 부족분을 현금/대기자금으로 추가 |
| 현금/대기자금 최소 비중 미달 | 약한 근거 종목부터 감액해 현금 확보 |
| 국내/해외/ETF 비중 범위 과도 이탈 | 경고 섹션에 기록, 필요 시 보수적 보정 |

권장 기본값:

| 항목 | 기본값 |
|------|--------|
| 단일 종목 최대 | 15% |
| 신규 종목 최대 | 10% |
| 단순 직접언급 신규 종목 권장 | 3~5% |
| 현금/대기자금 최소 | 10% |
| 현금/대기자금 최대 | 강제하지 않음 |

## 리포트 출력 계획

검증 후 리포트에 `비중 검증 결과` 섹션을 추가한다.

포함할 내용:

- LLM 제안 비중을 그대로 유지한 항목
- 단일 종목 상한 때문에 감액한 항목
- 합계 100% 보정을 위해 현금으로 이동한 비중
- 현금 최소 비중 확보를 위해 조정한 항목
- 메르 직접 비중과 AI 제안 비중이 달랐던 경우

예시:

```markdown
## ✅ 비중 검증 결과

- 합계 보정: 103% → 100%
- NVIDIA: 18% 제안 → 단일 종목 상한 15%로 조정, 3% 현금 이동
- 현금/대기자금: 7% → 최소 현금 10% 기준으로 보정
- 메르 직접 비중: 없음. AI 해석 비중을 코드 가드레일로 검증함.
```

## 메르 직접 포트폴리오와의 관계

메르가 직접 포트폴리오나 비중을 제시한 경우, AI 해석보다 직접 제시값을 우선합니다. AI가 다른 비중을 제안했더라도 코드나 후처리에서 직접 제시값을 보존해야 합니다.

메르 직접 포트폴리오와 AI 해석 포트폴리오가 다를 경우 숨기지 않고 차이점을 기록합니다.

| 상황 | 처리 |
|------|------|
| 메르 직접 비중 있음 | 직접 비중 우선 |
| 메르 직접 종목만 있음 | LLM이 비중 제안, 코드 가드레일 적용 |
| 메르 직접 포트폴리오와 AI 해석 차이 | `비중 검증 결과` 또는 별도 섹션에 기록 |

## 구현 순서 제안

1. `system_prompt.py` 표 형식에 `비중산정근거` 추가
2. `portfolio_validation.py`에서 6컬럼/7컬럼 추천 표 모두 파싱 가능하게 확장
3. 비중 합계 계산 함수 추가
4. 현금/대기자금 row 찾기 또는 생성 함수 보강
5. 단일 종목 상한 및 신규 종목 상한 적용
6. 현금 최소 비중 보정
7. `비중 검증 결과` 섹션 추가
8. `track_returns.py`, `generate_dashboard.py`, `telegram_notify.py`가 변경된 표 형식을 문제없이 읽는지 확인
9. GitHub Actions 실제 실행으로 성공/Telegram/HTML/PNG까지 검증

## 주의할 점

- 검증을 위해 Gemini API를 추가 호출하지 않는다.
- 비중 보정은 공격적으로 하지 말고, 불확실하면 현금으로 이동한다.
- 기존 `추천 검증 결과`와 새 `비중 검증 결과`는 역할이 다르다.
- 사용자에게 보이는 최신 추천은 항상 검증 완료된 `latest.md` 기준이어야 한다.
- `portfolio_state.json`은 내부 상태이며, 최신 추천 비중의 1차 기준이 아니다.
