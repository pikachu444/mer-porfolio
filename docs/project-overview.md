# 메르AI 포트폴리오 프로젝트 개요

## 목적

이 프로젝트는 메르 네이버 블로그 글을 수집해 모델 포트폴리오를 자동으로 갱신하고,
투자자가 Telegram 메시지와 HTML 대시보드에서 같은 내용을 확인할 수 있게 하는 시스템이다.

이 시스템은 메르 블로거의 실제 계좌를 복제하지 않는다. 블로그 글에 나타난 직접 판단과
AI의 해석을 구분해 만든 참고용 모델 포트폴리오다.

## 투자자에게 보이는 결과물

| 결과물 | 위치 | 기준 자료 |
|---|---|---|
| Telegram 메시지 | Telegram 봇 | 현재 모델 포트폴리오 상태 |
| HTML 대시보드 | `output/dashboard.html` | 현재 모델 포트폴리오 상태 |
| Markdown 보고서 | `output/report_YYYYMMDD.md` | 현재 모델 포트폴리오 상태 |
| Telegram 차트 이미지 | `output/chart_latest.png` | 현재 모델 포트폴리오 상태 |
| 수익률 표와 흐름 | HTML, Telegram | 현재 모델 포트폴리오 상태 + 수익률 계산 자료 |

사용자 출력의 기준은 `output/portfolio_state.json`에 저장된 현재 모델 포트폴리오 상태다.
`latest.md`는 사용자 출력 기준으로 사용하지 않는다.
보고서 기준일과 파일명은 한국시간(`Asia/Seoul`) 기준으로 계산한다. GitHub Actions 실행 환경의
UTC 날짜가 아니라 투자자가 메시지를 받는 한국 날짜를 사용한다.

## 핵심 원칙

- 메르의 직접 판단과 AI의 추론을 반드시 구분한다.
- AI의 추론을 메르의 직접 추천처럼 표시하지 않는다.
- 모델 포트폴리오 편입과 메르의 실제 보유를 혼동하지 않는다.
- 종목 변경은 근거 글, URL, 판단일을 추적할 수 있어야 한다.
- 원문 글을 특정할 수 없는 과거 보강 근거는 원문 근거처럼 표시하지 않고 과거 보고서 근거로
  구분한다.
- 새로운 근거 없이 판단과 목표 비중을 임의로 바꾸지 않는다.
- 현금성/방어성 비중은 단순 잔여값이 아니라 리스크 관리 요소로 본다.
- 기본 방어 기준은 현금성 20%이며, 큰 이벤트나 시장 리스크가 커진 구간에서는 이보다 높은
  현금성 비중을 제안할 수 있다.
- 승인 근거가 없는 기존 보유 종목은 `admin_review_queue`로 이동시키고 승인 포트폴리오에서
  행정적으로 편출한다. 관리 큐와 provenance 상태는 일반 Telegram·HTML에 표시하지 않는다.
- 오늘의 상태는 과거 LLM action이 아니라 승인 목표비중과 최신 실제비중, 리밸런싱 밴드,
  최소 조정 기준으로 새로 계산한다.
- 수익률 계산 자료에 종목이 빠져도 현재 모델 포트폴리오에서 종목을 숨기지 않는다.
  이 경우 수익률은 `집계 전`으로 표시한다.
- 동일 종목을 청산한 뒤 재편입할 수 있으므로 과거 종료 episode와 현재 active 포지션은 함께
  존재할 수 있다. 코드 오기는 정규화하되 과거 청산·실현손익 이력은 삭제하지 않는다.

## 사용자 출력 정책

Telegram은 링크 안내가 아니라 모바일 요약 대시보드다. 기준일·수익률 기준일·최대 낙폭·
기준 포트폴리오 대비 수익률 차이(%p)·자산배분·전체 보유 종목·오늘의 조정·핵심 인사이트를
한 번에 제공한다. 보유 종목을 생략하고 HTML로 넘기지 않는다. HTML은 원문 근거·판단 이력·
차트·전체 관심종목 같은 상세 정보를 제공하며 내부 검증 오류와 관리자 큐는 포함하지 않는다.

## 분석 보류 정책

신규 글 요약이나 LLM 투자 판단이 한도 초과, 일시 장애, 응답 형식 오류로 완료되지 않을 수 있다.
이때 새 투자 판단을 임의로 만들지 않는다.

대신 현재 포트폴리오 상태를 유지하고 오늘 날짜 보고서, HTML, Telegram 메시지를 생성한다.
사용자 출력에는 내부 예외 문구 대신 `오늘 제안된 조정안이 내부 검증 기준을 충족하지 않아
기존 포트폴리오를 유지합니다.` 같은 일반 문구만 표시한다. 보류된 글 제목은 필요할 때만
간단히 남기고, 원문 오류·stack trace·validator 문자열은 관리자 로그에서만 확인한다.

글 요약과 원문 근거 추출은 `gemini-3.1-flash-lite`, 구조화 투자 판단은
`gemini-3.5-flash`를 사용한다. 모델 종료·권한 오류, 무료 한도, 일시 장애를 구분하고 판단이
완료되지 않으면 기존 포트폴리오와 목표 비중을 유지한다. 사용자 보고서는 별도 LLM을 호출하지
않고 검증된 상태에서 결정론적으로 생성한다.

## 리밸런싱 정책

- 매일 1회 신규 글을 수집한다.
- 신규 투자 관련 글이 있으면 포트폴리오 판단을 실행한다.
- 마지막 실제 리밸런싱 이후 7일이 지나고 그 기간에 신규 투자 관련 글이 있으면 누적 글로
  논지와 전 종목을 재검토한다. 기준일이 없는 최초·수동 리밸런싱은 최근 14일의 원문·요약을
  분석 근거로 사용한다.
- 신규 글이 없어도 실제 NAV drift, 변동성, MDD, Watchlist 만료와 기업행동은 매일 점검한다.
  7일 논지 재검토 날짜만 다음 관련 글까지 갱신하지 않는다.
- 리밸런싱 때는 종목별 방향성뿐 아니라 주식 노출, 현금성 비중, 재검증 필요 포지션을 함께 본다.
- 신규 매수로 현금성 비중이 20% 아래로 내려가면 그 이유가 판단 결과에 명시되어야 한다.

## 정상화된 전략 정책

- 상태 2.1은 원문 근거가 검증된 불변 `signal_events`와 Watchlist archive를 보존한다.
- 메르 직접 원문 신호와 AI 추론은 최초 출처를 유지하며, 후속 AI 관리 판단이 출처를 덮지 않는다.
- 기존 2.0 포지션은 출처를 추정하지 않고 `legacy_unvalidated`로 격리한다.
- 전략 예산은 패시브 20%, 메르 원문 신호 40%, AI 추론 20%, 현금 20%이며 미충족분은 현금이다.
- 메르 종목 5%, AI 종목 2%, 발행사 5%, 테마 15%, 국가 55% 상한과 12% 변동성 목표를 적용한다.
- 주간 리밸런싱은 전 종목을 검토하고 실제 NAV 비중이 목표에서 50bp 이상 벗어난 경우 거래한다.
- 사용자 상태 정책은 `rebalance_band_pct=0.50`, `minimum_trade_weight_pct=0.50`,
  `minimum_trade_amount=0.50` 모델단위를 기본값으로 사용하며 환경변수로 조정할 수 있다.
  실제 주문을 제출하지 않으므로 사용자 문구는 검토 단계로 제한한다.
- 일반 리밸런싱의 총 거래 명목(`Σ|목표-실제|`, 현금 중복 제외)은 15%로 제한한다. 강제 위험 축소,
  전량 청산·논지 무효화, 패시브 슬리브 최초 편입과 그 재원 매도는 상한에서 제외한다.
- clean v4 성과원장은 과거 검증 전 원장을 분리 보존하고 비용·실제 현금·배당·분할·최대 낙폭·벤치마크를 표시한다.
