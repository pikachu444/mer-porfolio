# 운영 방식

이 프로젝트는 메르 블로그 글을 수집하고, LLM으로 글의 투자 논지와 근거를 정리해 Telegram과 HTML 대시보드로 전달한다.

## 실행 흐름

1. RSS와 원문에서 새 글을 수집하고 `output/posts_db.json`에 요약을 저장한다.
2. 투자 관련 글만 LLM 판단 입력으로 사용한다.
3. 원문 근거가 있는 종목 또는 산업 논지를 표현하는 섹터 ETF만 포트폴리오 후보로 검토한다.
4. 결정 결과를 `output/portfolio_state.json`에 반영하고, 성과 원장과 대시보드를 갱신한다.
5. Telegram에는 핵심 요약·인사이트·보유 종목·비중·당일 변경을 보낸다.

## 포트폴리오 원칙

- 메르의 직접 언급, 메르 산업 논지 기반 AI 추론, 단순 언급을 구분한다. 단순 언급은 편입하지 않는다.
- 개별주는 목표 비중 10%, 섹터·산업 ETF는 30%를 넘길 수 없다.
- 승인된 목표 비중의 합계 외 잔여 비중은 현금으로 둔다. 현금을 채우기 위해 종목을 추가하거나 비중을 키우지 않는다.
- KOSPI200과 S&P500은 보유 자산이 아닌 성과 비교용 벤치마크다.
- 광범위 시장 지수 ETF 자동 편입, 고정 슬리브, 점수·변동성 기반 배분은 사용하지 않는다.

## 운영 데이터

- `output/portfolio_state.json`: 다음 실행에 사용할 현재 포트폴리오 상태
- `output/model_portfolio_ledger.json`: 매입가·거래비용·NAV 이력을 포함한 성과 원장
- `output/performance_cache.json`: 성과 계산 및 비교 벤치마크 캐시
- `output/posts_db.json`: 수집 글과 요약 캐시

정책 정정으로 현재 보유에서 제거된 자산의 과거 원장과 NAV 이력은 지우지 않는다. 이는 투자 판단에 따른 매도 기록으로 처리하지 않는다.

## 화면 역할

- Telegram은 기본 화면이다. 긴 내부 상태나 검증 오류 대신 사용자용 설명을 제공한다.
- HTML은 보조 화면이다. 현재 보유 종목을 표로 비교하고, 상세 근거·원문 링크·위험·무효화 조건을 확인한다.
